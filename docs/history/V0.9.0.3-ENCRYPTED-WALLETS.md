# GameCoin v0.9.0.3 Encrypted Wallet Maintenance

v0.9.0.3 is a chain-compatible wallet-security maintenance release for Public Testnet v4. It does not change consensus, the network ID, protocol 5, genesis, ports, block format, difficulty rules, rewards, maturity, or the application data directory.

## Encrypted wallet format

New wallets use wallet storage version 3. Public address metadata remains readable so the wallet can display balances, history, receive addresses, and mining reward addresses while locked. The deterministic master seed is stored only inside an authenticated-encryption envelope.

- Password KDF: Argon2id
- Memory cost: 64 MiB
- Iterations: 3
- Parallel lanes: 4
- Salt: 128 bits, random per encryption/re-encryption
- Cipher: AES-256-GCM
- Nonce: 96 bits, random per encryption/re-encryption
- Encrypted secret: 256-bit deterministic master seed plus an authenticated hash of protected public wallet metadata

The plaintext JSON must not contain `master_seed` or `private_key` fields in wallet version 3.

## Locked behavior

An encrypted wallet can remain locked while it:

- displays already-derived receive/mining/change addresses;
- checks balances and transaction history;
- receives funds;
- mines to an already-derived mining reward address;
- changes which already-derived receive address is displayed.

The password is required to:

- sign/spend transactions;
- derive a new receive or change address;
- change the wallet password.

## Legacy wallet migration

Version 1/2 plaintext wallets remain readable for migration. The GUI `Security` action can encrypt an existing wallet in place and deliberately retains a timestamped plaintext safety backup. The user must protect or securely destroy that plaintext backup after verifying the encrypted wallet.

Importing a legacy plaintext wallet into v0.9.0.3 requires setting a password; the imported copy is written in encrypted version-3 format while the source file is left unchanged.

## Password changes

Changing the password preserves the wallet ID, addresses, deterministic seed, and funds while generating a fresh Argon2 salt, AES-GCM nonce, and ciphertext.

## Test expectations

Before mainnet rehearsal, verify all of the following on Windows:

1. create an encrypted wallet and inspect field names only;
2. confirm no plaintext master seed/private key appears on disk;
3. wrong password cannot sign or derive new addresses;
4. correct password can send and derive addresses;
5. backup/import preserves encryption and still requires the original password;
6. legacy migration preserves addresses and balance;
7. password change invalidates the old password and preserves wallet identity;
8. restart leaves the wallet encrypted and locked on disk.
