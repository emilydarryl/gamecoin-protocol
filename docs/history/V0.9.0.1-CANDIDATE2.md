# GameCoin v0.9.0.1 Mainnet Candidate 2

Public Testnet v4 exists to prove the consensus rules planned for mainnet without changing the stable v2 history.

Implemented candidate rules include integer chainwork, greatest-valid-work fork choice, median-time-past/future-time checks, hardened timing inputs to difficulty adjustment, 100-block coinbase maturity, fee collection, strict address checksums, and resource ceilings.

The next validation phase is multi-peer/fork testing, Windows build testing, separate VPS v4 seed deployment, and a long soak run. Mainnet genesis must not be created until those tests are complete and the consensus specification is frozen.


## Why v4 exists

Public Testnet v3 exposed two timing defects during its first live mining run: difficulty estimated solve time from successive median-time-past values, and the CPU miner kept the original template timestamp during long solves. At height 21 this caused the next difficulty to rise from about 63,424x to about 164,123x even after a very slow block. The v3 candidate was stopped rather than patched in place.

Candidate 2 keeps MTP for timestamp validity, refreshes miner nTime while hashing, uses adjacent validated block timestamps for difficulty timing, clamps individual timing samples, and limits upward adjustment more conservatively. Because these are consensus changes, v4 has a new network ID, protocol, genesis, ports, data directory, and installer identity.
